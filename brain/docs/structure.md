# Project Structure & Tooling

This document describes how the Knowledge OS repository is organized at the tooling
level — setup, skills, and conventions. For knowledge-base conventions (note types,
frontmatter, tags), see `brain/instructions/BRAIN-INSTRUCTION.md`.

Knowledge OS uses **pi** as its coding agent harness. Pi auto-discovers skills from
`brain/skills/` and reads `AGENTS.md` (generated by `setup.sh`) from the project root.

---

## Root structure

```
data/          ← user's knowledge base (notes, projects, journal, etc.)
brain/         ← the brain of knowledge OS
  skills/      ← modular skill packages
  instructions/
    BRAIN-INSTRUCTION.md  ← single source of truth for agent instructions
  scripts/
    kb-search/  ← shared vector search engine (ChromaDB + Ollama)
  docs/
    structure.md ← this file
configuration/ ← runtime configs (credentials, etc.)
```

---

## Single source of truth: brain/instructions/BRAIN-INSTRUCTION.md

The file `brain/instructions/BRAIN-INSTRUCTION.md` is the canonical agent instruction
file. `setup.sh` copies it to `AGENTS.md` in the project root — this is the file that
pi auto-reads at startup.

| Generated file | Purpose |
| --- | --- |
| `AGENTS.md` (project root) | pi auto-reads this from project root |

**Rule:** Always edit `brain/instructions/BRAIN-INSTRUCTION.md`. Never edit `AGENTS.md` directly.

---

## Pi settings

Pi configuration lives in `.pi/settings.json` at the project root:

```json
{
  "skills": ["../brain/skills"],
  "enableSkillCommands": true,
  "sessionDir": ".pi/sessions"
}
```

- `skills` points to the `brain/skills/` directory for auto-discovery
- `enableSkillCommands` enables `/skill-name` command triggers
- `sessionDir` stores session logs under `.pi/sessions/`

---

## Skills

Skills live in `brain/skills/<name>/` and are auto-discovered by pi via the
`.pi/settings.json` config. No symlinks needed.

Each skill folder contains at minimum a `SKILL.md` with YAML frontmatter (name +
description) and markdown body. Optional extras:

- `requirements.txt` — Python deps, auto-installed by `setup.sh`
- `scripts/` — helper scripts invoked by the skill
- `references/` — supporting documents and research notes
- `config.json` / `config.env` — skill-specific configuration (gitignored secrets go in `config.env`)

### Adding a new skill

1. Create `brain/skills/<name>/` with at minimum a `SKILL.md`
2. Run `./setup.sh` — it auto-discovers the folder and installs Python deps
3. If the skill needs Python deps, add `brain/skills/<name>/requirements.txt`

### Shared scripts

Skills that need vector search share a single engine at `brain/scripts/kb-search/`:

- `search.py` — semantic search with ChromaDB + Ollama embeddings
- `index.py` — build/rebuild the vector index
- `watch.py` — file watcher for automatic re-indexing

The search engine has its own isolated venv at `brain/scripts/kb-search/.venv/`.

## Setup script

```
./setup.sh             # install Python deps, setup ChromaDB, copy AGENTS.md
./setup.sh --unlink    # remove ChromaDB background service, remove AGENTS.md
```

What `setup.sh` does:

1. **Copies agent instructions** — `brain/instructions/BRAIN-INSTRUCTION.md` → `AGENTS.md` (pi auto-read from project root)
2. **Installs Python deps** — runs `pip install -r requirements.txt` for each skill that has one; skills with a `.use-venv` marker get an isolated venv
3. **Sets up git hooks** — copies hooks from `configuration/hooks/` into `.git/hooks/`
4. **Registers ChromaDB** — as a background service (launchd on macOS, systemd on Linux) that auto-starts on login

Scope: **project-local only** — no global directories are touched.

## Directory layout (tooling view)

```
brain/
  instructions/
    BRAIN-INSTRUCTION.md         ← single source of truth for agent instructions

  skills/
    <name>/
      SKILL.md                   ← skill instructions (required)
      requirements.txt           ← Python deps (optional)
      scripts/                   ← helper scripts (optional)
      config.json / config.env   ← runtime config (optional)

  scripts/
    kb-search/                   ← shared vector search engine
      .venv/                     ← isolated Python venv
      search.py
      index.py
      watch.py
      requirements.txt

  docs/
    structure.md                 ← this file

AGENTS.md → brain/instructions/BRAIN-INSTRUCTION.md  ← copied by setup.sh
.pi/
  settings.json                   ← pi configuration
  sessions/                       ← pi session logs
```

## What NOT to modify directly

| File / directory | Why |
| --- | --- |
| `AGENTS.md` (root) | Generated by `setup.sh` — edit `brain/instructions/BRAIN-INSTRUCTION.md` instead |
| `brain/scripts/kb-search/.venv/` | Managed by `setup.sh` — edit `brain/scripts/kb-search/requirements.txt` to add deps |
