# Project Structure & Tooling

This document describes how the repository is organized at the tooling level — symlinks, skills, and setup conventions. For knowledge-base conventions (note types, frontmatter, tags), see `brain/instructions/BRAIN-INSTRUCTION.md`.

---

## Root structure

```
data/          ← user's knowledge base (notes, projects, journal, etc.)
brain/         ← the brain of knowledge OS
  skills/      ← modular skill packages
  apps/        ← future apps (placeholder)
  instructions/
    BRAIN-INSTRUCTION.md  ← single source of truth for agent instructions

```

---

## Single source of truth: brain/instructions/BRAIN-INSTRUCTION.md

The file `brain/instructions/BRAIN-INSTRUCTION.md` is the canonical agent instruction file. It is **not** edited in-place at the repo root or in `.github/`. Those copies are symlinks created by `setup.sh`.

| Symlink target | Purpose |
| --- | --- |
| `CLAUDE.md` | Claude Code auto-reads this from project root |
| `.github/copilot-instructions.md` | GitHub Copilot reads this automatically |

**Rule:** Always edit `brain/instructions/BRAIN-INSTRUCTION.md`. Never edit the symlink targets directly.

## Skills

Skills live in `brain/skills/<name>/` and are symlinked into tool-specific directories by `setup.sh`.

| Source | Symlink target | Consumed by |
| --- | --- | --- |
| `brain/skills/<name>/` | `.claude/skills/<name>/` | Claude Code |
| `brain/skills/<name>/` | `.github/skills/<name>/` | GitHub Copilot |

Each skill folder contains at minimum a `SKILL.md` with instructions. Optional extras:

- `requirements.txt` — Python deps, auto-installed by `setup.sh`
- `scripts/` — helper scripts invoked by the skill
- `config.json` / `config.env` — skill-specific configuration (gitignored secrets go in `config.env`)
- `references/` — supporting documents and research notes

### Adding a new skill

1. Create `brain/skills/<name>/` with at minimum a `SKILL.md`
2. Run `./setup.sh` — it auto-discovers the folder and creates both symlinks
3. If the skill needs Python deps, add `brain/skills/<name>/requirements.txt`

## Setup script

```
./setup.sh                       # create all symlinks + install Python deps
./setup.sh --unlink              # remove all symlinks (does not touch source files)
source ./setup.sh env            # load KOS_ env vars into current shell
source ./setup.sh env --install  # load + persist env vars to ~/.zshrc (run once)
```

What `setup.sh` does:

1. **Discovers skills** — iterates `brain/skills/*/` automatically (no hardcoded list)
2. **Creates skill symlinks** — `brain/skills/<name>` → `.claude/skills/<name>` and `.github/skills/<name>`
3. **Creates context symlinks** — `brain/instructions/BRAIN-INSTRUCTION.md` → `CLAUDE.md` and `.github/copilot-instructions.md`
4. **Installs Python deps** — runs `pip install -r requirements.txt` for each skill that has one
5. **Loads env vars** (`env` subcommand) — exports `KOS_*` variables from `.env` into the current shell; must be `source`d

Scope: **project-local only** — no global directories (`~/.claude`, `~/.config`, etc.) are touched.

## Directory layout (tooling view)

```
brain/
  instructions/
    BRAIN-INSTRUCTION.md         ← single source of truth for agent instructions
    settings.json                ← single source of truth for Claude Code config

  skills/
    <name>/
      SKILL.md                   ← skill instructions (required)
      requirements.txt           ← Python deps (optional)
      scripts/                   ← helper scripts (optional)
      config.json / config.env   ← runtime config (optional)

.claude/                         ← generated by setup.sh (gitignored)
  skills/
    <name> → brain/skills/<name>

.github/                         ← generated by setup.sh
  copilot-instructions.md → brain/instructions/BRAIN-INSTRUCTION.md
  skills/
    <name> → brain/skills/<name>

CLAUDE.md → brain/instructions/BRAIN-INSTRUCTION.md  ← generated by setup.sh
```

## MCP servers

MCP server configuration lives in `.mcp/`. This is separate from skills and is not managed by `setup.sh`. See `.mcp/` for the server configs.

## What NOT to modify directly

| File / directory | Why |
| --- | --- |
| `CLAUDE.md` (root) | Symlink — edit `brain/instructions/BRAIN-INSTRUCTION.md` instead |
| `.github/copilot-instructions.md` | Symlink — edit `brain/instructions/BRAIN-INSTRUCTION.md` instead |
| `.claude/skills/<name>` | Symlink — edit `brain/skills/<name>` instead |
| `.github/skills/<name>` | Symlink — edit `brain/skills/<name>` instead |
